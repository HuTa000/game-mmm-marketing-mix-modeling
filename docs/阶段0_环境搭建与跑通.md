## 二、踩坑记录（8 个真实问题，全部已修复）

这些**就是阶段 0 的核心价值**——面试时讲这些比讲"我会调包"有说服力得多。

### 坑 1：Windows + PyMC 必须加 `if __name__ == "__main__":`

**现象**：脚本跑了 2 小时没结果，看似"卡死"。
**真实原因**：PyMC 多链采样用 `multiprocessing` 开子进程。Windows 用 `spawn` 模式，子进程会**重新 import 主脚本**。没加 main 保护时，子进程又去开子进程 → 抛 `RuntimeError` 并被吞掉。

```
RuntimeError: An attempt has been made to start a new process before 
the current process has finished its bootstrapping phase.
```

**修复**：所有建模代码放进 `if __name__ == "__main__": main()`。
**代价对比**：修复后同样任务 **48 秒**跑完。

> 💡 这是 Linux/Mac 不会遇到的坑（它们用 fork）。**面试加分点**。

---

### 坑 2：采样参数必须放顶层 kwargs，不能塞进 `sample_kwargs`

**现象**：我传了 `chains=2, draws=300`，但日志显示 `4 chains in 4 jobs`，采样奇慢。
**原因**：PyMC-Marketing 1.x 中 `sample_kwargs` **只给 advi/map 等变分方法用**；MCMC 参数必须作为顶层关键字直接传给 `fit()`。

```python
# ❌ 错误：chains/draws 被静默忽略，用了默认 4链×1000步
mmm.fit(X, y, method="mcmc", sample_kwargs={"chains": 2, "draws": 300})

# ✅ 正确
mmm.fit(X, y, method="mcmc", chains=2, draws=300, tune=300,
        nuts_sampler="numpyro", target_accept=0.95)
```

**教训**：库里"静默忽略参数"是最危险的 bug 类型。

### 坑 6：必须做数据标准化

**现象**：不做标准化时，截距被估成 **−110.9**，业务上无法解读。
**原因**：各渠道花费量级差异大（kol 均值 3 万 vs google 16 万），却共用同一套先验 → 模型只能"把截距推成负数"来抵消媒体贡献的超额部分。

**修复**：渠道除以自身均值、y 除以均值，变成"相对平均投放的倍数"。

**效果**：divergences 从 **33 → 5**（降 85%）。

---

### 坑 7：Adstock 的 `l_max` 与 `decay` 必须联动

**核心公式**：Adstock 把花费放大的**累积倍数 = 1 / (1 − decay)**

| decay | 累积倍数 | 含义 |
|---|---|---|
| 0.2 | 1.25× | 效果很快消失 |
| 0.35 | 1.54× | |
| 0.5 | 2.00× | |
| 0.7 | **3.33×** | 长期品牌效应 |
| 0.9 | **10×** | 极持久 |

**踩坑实例**：我第一版玩具数据里 kol 用 `decay=0.7`，累积倍数 3.33 倍（其他渠道才 1.4），导致 **kol 花费最少（3.29）却贡献最高（161）**。
→ 这不是模型错，是**数据生成机制设计不当**。

**工程规则**：
- `l_max` 应满足 `decay^l_max < 1%`（即 6 周后残留可忽略）
- decay=0.45 → l_max=6 ✓（0.45⁶ ≈ 0.8%）
- 若 decay 高但 l_max 小，会**截断**长尾效应

---

### 坑 8：数据生成用标准 MMM 形式，别加额外变换

```python
# ✅ 标准形式
y = intercept + trend + season + Σ_c [beta_c · adstock(x_c)] + noise
```
**不要**做"平均花费归一 × beta"这类变换，会让渠道间失去可比性。

这是**证明 MMM 实现正确性的标准做法**——用已知参数造数据，看模型能否把它们"猜"回来。

**测试设置**：156 周 × 5 渠道，标准 MMM 形式生成数据。

**结果**：

| 渠道 | 真实 decay | 估计 decay [94% CI] | 是否命中 |
|---|---|---|---|
| facebook | 0.35 | 0.372 [0.15, 0.59] | ✅ |
| google | 0.40 | 0.383 [0.31, 0.46] | ✅ |
| tiktok | 0.25 | 0.281 [0.23, 0.33] | ✅ |
| youtube | 0.20 | 0.237 [0.01, 0.55] | ✅ |
| kol | 0.45 | 0.313 [0.07, 0.58] | ✅ |

**decay 回收率 5/5（100%）** —— 模型确实从数据中"发现"了真实的广告衰减机制。

**beta 方向也正确**：真实 tiktok=2.20（最高）→ 估计 2.256（最高）✅

**诊断指标**：
- divergences: 13/1000 (1.30%)
- R-hat > 1.01 的参数: 3/17（DEMO 模式 2 链的正常水平）

> 🎯 **面试金句**："我用参数回收检验验证了模型实现的正确性——用已知的衰减率生成数据，再让模型去估计，5 个渠道的衰减率真值全部落入 94% 可信区间。这证明模型不是凑数字，而是真的学到了机制。"

## 四、遗留问题：一个重要的可识别性难题（→ 阶段 2 解决）

### 现象
贡献分解结果**偏离真实值**：

| 渠道 | 真实占比 | 模型估计占比 |
|---|---|---|
| facebook | 8.8% | 明显偏高 |
| google | 27.6% | 接近 |
| tiktok | 22.3% | 接近 |
| youtube | **3.7%** | **40.5%** ❌ |
| kol | 5.7% | 29.2% ❌ |

### 根因分析

`compute_mean_contributions_over_time` 返回**标准化空间**的值（`target_scale=2.32` 未自动还原）。总 y 标准化后 = 156.0，而各渠道之和 = 210.3 —— **贡献被系统性高估**。

深层原因：**Hill 饱和函数与 `beta` 的乘积存在尺度不可识别性**。
- Hill 在 x≈1（平均投放）附近输出约 0.5
- 若 beta 估大了，饱和参数的"半饱和点"可以相应调整来补偿
- **两条路径产生同样的似然** → 后验变宽、贡献分解不稳定

### 这正是 MMM 的核心难点之一

| 难点 | 在本项目的体现 |
|---|---|
| **可识别性** | beta 与饱和参数互相"顶替" |
| **共线性** | 大促周全渠道同步加投（我故意造的，模拟真实场景） |
| **内生性** | 加投是因为预期会大卖 |

### 阶段 2 的解决路线（预告）

1. **信息先验**：用历史 ROI 范围约束 `saturation_beta`，给出业务上合理的区间
2. **目标尺度校准**：正确使用 `target_scale` 做还原，或改用 `add_original_scale_contribution_variable()`
3. **多链正式采样**：`--full` 模式 4 链 × 1200 draws 改善收敛
4. **提供独立变异**：各渠道的独立脉冲（已做）+ 后续加 lift test 校准
5. **共线性诊断**：VIF + 相关性矩阵（阶段 1 EDA 必做）

## 六、关键代码片段（可复用）

```python
# ============ 正确的 MMM 调用模板 ============
import os
os.environ.setdefault("PYTENSOR_FLAGS", "cxx=")   # 绕开编译器问题

from pymc_marketing.mmm import MMM, GeometricAdstock, HillSaturation

mmm = MMM(
    date_column="date",
    channel_columns=channels,
    target_column="y",
    adstock=GeometricAdstock(l_max=6),   # l_max 与 decay 联动
    saturation=HillSaturation(),
    yearly_seasonality=2,
)

idata = mmm.fit(
    X_scaled, y_scaled,
    method="mcmc",
    chains=4, cores=4,          # 顶层 kwargs，不是 sample_kwargs！
    draws=1200, tune=1200,
    random_seed=42,             # 保证可复现
    nuts_sampler="numpyro",     # Windows 友好
    target_accept=0.95,         # 减少 divergences
)

# ---- 诊断 ----
import arviz as az
s = az.summary(idata, ci_prob=0.94)          # 不是 hdi_prob
n_div = int(idata.sample_stats["diverging"].sum().values)

# ---- 变量名（1.x）----
# intercept_contribution / saturation_beta / adstock_alpha
# saturation_kappa / y_sigma
```
