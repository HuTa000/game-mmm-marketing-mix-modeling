## 1. 这一页解决什么问题

阶段 2 的建模脚本能跑出正确的数字，但只有写它的人看得懂。这一页要解决三件事：

| 问题 | 阶段 2 的形态 | 本页的形态 |
|---|---|---|
| **耗时** | `python src/stage2_model.py`，等 10~20 分钟 | 首次进入自动复用已有后验（**毫秒级**）；需要重跑时给出分阶段进度与耗时预期 |
| **可读性** | 终端里一片 `az.summary` 输出 | 6 个 Tab，每个先给"业务问题"再给图，最后给"这张图怎么用" |
| **边界** | 结论写在脚本注释里 | 「这套结论的边界在哪」独立成一个 Tab，主动讲结构性不可识别 |

页面顶部常驻一条状态条：数据源、渠道数、控制变量数、模型来源、后验样本量、收敛是否达标。
**用户第一眼就知道"现在看到的结果是哪来的、可不可信"。**

## 3. 六个区块：每个对应一个业务问题

### 3.1 「这套数字能拿去汇报吗？」—— 结果可信吗

**两段式检查**，因为它们是不同性质的问题：

**Part 1 · MCMC 收敛**（决定后验分布可不可信）

| 指标 | 实测 | 判据 | 不达标意味着 |
|---|---|---|---|
| 最大 R-hat | **1.0021** | < 1.01 | 多条链没采到同一个分布，后验均值不可信 |
| 最小 ESS | **2,815** | > 400 | 分位数不稳，可信区间会偏窄 |
| 发散样本 | **0 / 6,000** | < 2% | 采样器撞上几何病态区 |
| 截距 | **+0.429** | > 0 | 为负 → 媒体贡献虚高 4~8 倍 |

**Part 2 · 模型自洽性**（算 ROI 之前的前置关卡）

| 检查 | 含义 | 不通过意味着 |
|---|---|---|
| 可加性：Σ分量 = μ | identity link 下必须成立 | 贡献分解表加起来对不上总收入 |
| 截距为正 | 基线没被渠道挤负 | ROI 整体偏乐观 |
| 预测拟合 | 模型总预测 vs 历史总收入 | 没抓住主要结构，不必急着解读渠道 |

实测三项全过（可加性偏差 +0.0162%，预测偏差也在 5% 内）。

---

### 3.2 「哪个渠道该加钱，哪个该砍？」—— 渠道 ROI

**关键设计：给区间，不给点估计。**

ROI = 1.24 这句话没有决策价值；"ROI 有 94% 概率落在 [1.11, 1.39]" 才能支撑动作。

颜色**按决策方向**给，而不是按渠道：

| 区间位置 | 颜色 | 结论文案 |
|---|---|---|
| 下界 > 1 | 红（加大投入） | 整段区间 > 1，加预算有正当理由 |
| 上界 < 1 | 绿（减少投入） | 整段区间 < 1，应缩减或重做素材/定向 |
| 跨越 1 | 灰（不确定） | 证据不足，先做小规模增量实验 |

与红涨绿跌的中国习惯一致：红 = 加大投入。

实测结果（内置模拟数据）：

| 渠道 | ROI 均值 | 94% 区间 | P(ROI>1) | 结论 |
|---|---|---|---|---|
| tiktok | 2.497 | [2.449, 2.548] | 100% | 加预算 |
| google | 1.563 | [1.510, 1.621] | 100% | 加预算 |
| kol | 1.241 | [1.108, 1.387] | 100% | 加预算 |
| facebook | 1.069 | [1.002, 1.142] | 97.3% | 加预算（临界） |
| youtube | 0.656 | [0.581, 0.740] | **0%** | **该砍** |

`youtube` 的整段区间都在 1 以下 —— 这是本页最"硬"的一个业务结论。

---

### 3.3 「花出去的钱换回了什么？」—— 收入怎么分

这里踩了一个**必须讲清楚的坑**，最后拆成两张口径不同的表：

#### 表 A · 总量账（有总量含义）

| 分量 | 金额 | 占收入比 |
|---|---|---|
| 基线（自然增长） | 19,585.9 万元 | **42.9%** |
| tiktok | 11,068.4 万元 | 24.3% |
| google | 8,046.0 万元 | 17.6% |
| facebook | 3,368.7 万元 | 7.4% |
| kol | 1,957.2 万元 | 4.3% |
| youtube | 1,569.4 万元 | 3.4% |

守恒检验：各分量之和与真实总收入的残差 **0.0031%**。

#### 表 B · 波动账（只有振幅有意义）

| 分量 | 逐周振幅 | 年度净额 | 为什么净额接近 0 |
|---|---|---|---|
| 季节性（Fourier） | ±12.4 万元 | 7.4 万元 | Fourier 基在完整年度上积分为 0 |
| 控制变量 | ±18.7 万元 | 0.0 万元 | 控制变量已标准化（均值 0）+ 收缩先验 |

> **为什么必须分开**：季节性在一个完整年度上的总和**恒等于 0**（156 周 = 3 个完整年度，
> sin/cos 基完全抵消）。把它的 `sum` 当成"季节性贡献了 X 万元"是 MMM 汇报里
> 最常见的错误之一。它真正的价值是：**不让模型在旺季把"季节本该有的增量"
> 误记到渠道头上** —— 不建模季节性，Q4 的渠道 ROI 会系统性虚高。

---

### 3.4 「广告效果衰减多快？什么时候饱和？」—— 参数与后验

用可选参数的单选 + 箱线图 + 轨迹图呈现 4 个核心参数：

| 参数 | 业务含义 | 本数据的实测 |
|---|---|---|
| `adstock_alpha` λ | 投放节奏：λ 高适合脉冲式大促，λ 低适合持续小额 | 0.26~0.42（各渠道） |
| `saturation_kappa` κ | 半饱和点 = "还能加多少"的直接答案 | κ 是平均花费的 1.6~2.8 倍 |
| `saturation_slope` s | S 形陡峭度，**最难识别**（区间最宽） | 约 1.7 |
| `saturation_beta` β | 标准化尺度的曲线高度，**不是 ROI** | 约 1.0~4.0 |

轨迹图的作用：4 条链应该像"同一团毛线"，分层带子 = 没混匀 = R-hat 会超标。

---

### 3.5 「模型估得准吗？」—— 参数回收

**唯一能"对答案"的场景**（数据是自己生成的）。两个指标：

| 指标 | 实测 |
|---|---|
| 94% 区间命中真值 | **7 / 10** |
| **ROI 排序与真值一致** | **✅ 完全一致** |

```
估计：tiktok > google > kol > facebook > youtube
真实：tiktok > google > kol > facebook > youtube
```

> **有一个坑值得单独说**：最初我把 `saturation_beta` 的估计值放在 "ROI" 列去和真值比，
> 得到 `估 4.0 vs 真 2.3`，看起来"模型严重高估"。实际上 β 是**标准化空间**的
> 曲线高度参数，量纲与 ROI 完全不同。改成用 `roi_posterior`（元收入/元花费）
> 对照后，命中率从 5/10 升到 7/10，且排序完全一致。
> **口径对齐比算法精度更值得警惕。**

---

### 3.6 「这套结论的边界在哪？」—— 局限与缓解

主动量化**结构性不可识别性**：

```
y(t) = 基线常数 + Σ渠道贡献(t) + 季节(t) + 控制(t) + ε
```

把「基线常数」加 α、同时把每个渠道的恒定分量减 α，预测值完全不变 ——
数据无法分辨。实测媒体贡献里 **57.0%** 是恒定分量，与基线常数不可分离
（混淆量 1.33 倍）。

然后给出一张四行表，把 MMM 的四个软肋逐条对齐到"本数据里的表现 / 已做的缓解 / 还缺什么"：

| 软肋 | 本数据表现 | 已做缓解 | 还缺 |
|---|---|---|---|
| 内生性 | 单渠道散点呈上凸（高花费周=大促周） | 控制变量 + 趋势项；探索页"毛关系 vs 净关系"对照 | geo-lift / pause test |
| 渠道共线性 | 最大 VIF 1.10（不共动，**有利**） | 建模前先看 VIF 与相关矩阵 | 真实业务常共动，需实验设计 |
| 遗漏变量 | 控制变量被收缩到接近 0，影响被吸进基线 | 显式建模 4 个控制 + 收缩先验 | 更多可观测混杂（KOL 档期等） |
| 结构性不可识别 | 恒定分量占 57% | 用 OLS 可识别水平而非真值设截距先验 | 多市场数据 / 实验校准 |

## 4. 三条硬性要求怎么落地

### 4.1 建模耗时长 → 两条路径 + 三级缓存 + **诚实的进度**

```
         ┌─ 路径 A：复用阶段 2 后验（仅内置数据）
         │     重建模型结构 + 注入后验，不采样 → 毫秒级
进入页面 ─┤
         └─ 路径 B：在本页拟合（任意数据）
               ① 先查磁盘缓存（数据指纹 × 超参哈希）→ 命中则直接还原
               ② 未命中才真正采样 → 结果落盘
```

三级缓存各司其职：

| 层级 | 手段 | 存什么 |
|---|---|---|
| L1 会话 | `st.session_state` | 完整结果（含 mmm 对象），**切页不重算** |
| L2 进程 | `cache_resource` | 预训练 bundle（含 mmm，不可序列化） |
| L3 磁盘 | `outputs/reports/app_fit_<key>.pkl` | 后验 + 配置，**跨浏览器重启**可还原 |

缓存键 = `数据指纹(sha1) × 超参哈希`。**这是正确性问题**：少了数据指纹，
用户换一份数据却命中旧模型，页面会展示与当前数据无关的 ROI 且不报错。

> **关于进度条的一个诚实选择**
> NUTS 采样是**阻塞调用**，`st.progress` 在采样期间无法刷新。
> 所以这里不在采样时给一个卡在 40% 的假进度条，而是：
> 采样**前**明确告知"共 12,000 次后验抽样，典型耗时 3~10 分钟"，
> 采样**后**补报实际耗时。用户知道要等多久，比看一个不动进度条更有安全感。

### 4.2 窄屏适配

- 所有 Plotly 图 `responsive=True`，图例置顶（不压数据）；
- 图高按内容动态计算（森林图 `90 + 42×渠道数`）；
- 表格走 `ui.dataframe`（全宽 + 横向滚动），不做多列硬挤；
- KPI 卡片 `per_row` 控制：3 项时一行、5 项时按 5 列。

### 4.3 业务决策导向

每个 Tab 固定三段式：**业务问题 → 图 → 🩺 这张图怎么用**。
「怎么用」里给的是**动作**，不是统计量：

- "λ 高的渠道适合集中投、拉长观察窗；λ 低的需要持续喂"
- "当前花费离 κ 越远，加钱越有效"
- "不要拿 β 直接比 ROI（口径不同）"
- "可以对外说相对量，不要对外说绝对量"

## 5. 踩的坑与根因

### 坑 1 · `dims=""` 应为 `dims=()`

```
ValueError: Channel scaling dims ('',) must contain (), 'channel', and 'date'
```

报错信息极其误导（"必须包含空元组"，而参数就是空元组）。
库内校验是 `set(scaling.channel.dims).difference([*self.dims, "channel", "date"])`；
`dims=""` 会被规范化成 `("",)`，差集非空 → 抛错。写成 `dims=()`（元组）即可。
`mmm_core.py` 原文是元组，我在新代码里手打成字符串才复现了这个错误。

### 坑 2 · `control_columns` / `yearly_seasonality` 必须"**不传**"，不能传空值

```python
control_columns: list[str] | None  = Field(min_length=1)   # 传 [] → ValidationError
yearly_seasonality: int | None     = Field(gt=0)           # 传 0  → ValidationError
```

**而且降级路径也必须按条件传参**：最初的降级逻辑退回 `mmm_core.build_mmm_safe`，
它在无控制变量时会把 `[]` 传进去 —— 等于降级也失败，异常直接抛到页面。
现在降级路径改用 `_build_mmm_direct(cfg, ctrl, custom_prior=False)`，两个边界都覆盖。

### 坑 3 · 复用路径上"预测精度"检查会静默消失

`mmm_core.check_model_sanity` 内部调 `mmm.predict()`。在"注入后验"的复用路径上，
`constant_data` 里的数组是 `MaskedArray`，PyTensor 编译期抛
`Unsupported array type: numpy.ma.MaskedArray` → 被 `try/except` 吞掉 →
**自洽性三项变成两项，页面不报错但少了一项检查**。

修法：直接读后验里的 `mu`（模型对 y 的期望）并乘回 `target_scale`。
数学等价、无需重新编译计算图：
`pred_sum = mu.mean(axis=(0,1)).sum() × target_scale`。

### 坑 4 · 季节项与控制的"总量占比"没有意义

第一版把季节/控制也放进"收入构成占比"表。结果是：

- 季节项占比 **0.0002%**（Fourier 基整年度积分为 0）
- 控制变量净额 **7.45e-13**（标准化 + 收缩先验）

数字"正确"但**完全没有解释力**，读者会以为"季节性对收入没影响"。
改为拆成「总量账 / 波动账」两张表，用**振幅**而非总量描述它们。

### 坑 5 · 回收表口径污染（见 3.5）

`saturation_beta` 与 ROI 混在同一列 → 得出"模型严重高估"的错误结论。

## 8. 面试可讲的三个点

**① 「你怎么知道模型是对的？」**
> 三条线：MCMC 诊断（R-hat 1.0021 / 0 发散 / ESS 2815）、
> 模型自洽性（可加性偏差 0.0162%、预测偏差在 5% 内）、
> 参数回收（用已知真值的模拟数据，ROI 排序完全一致）。
> 而且我把这些检查写成了 136 条可回归的断言，改代码就会跑。

**② 「MMM 最容易被误用在哪？」**
> 结构性不可识别。媒体贡献里有 57% 是恒定分量，与基线数学上不可分。
> 所以我的建议只基于**排序**和**增量**，不说"媒体一共创造了多少钱"。
> 要收窄只能靠外部实验（geo-lift / pause test）。

**③ 「一个耗时 10 分钟的任务，你怎么做产品化？」**
> 两条路径：能复用就复用（毫秒级），必须重跑就先查磁盘缓存
> （键 = 数据指纹 × 超参哈希，避免换数据命中旧模型的静默错误）。
> 进度上不给假进度条 —— NUTS 是阻塞采样，刷不了 UI，
> 所以我在采样前把样本量和耗时档位讲清楚，采样后补报实际耗时。
