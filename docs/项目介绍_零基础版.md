# 游戏出海广告效果分析 —— 零基础读本

> 这份文档假设你**完全不懂数据分析、不懂编程、不懂广告投放**。
> 全文不用术语堆砌，凡出现专业词，都在**同一段里**用大白话解释掉。
> 读完你会知道：这个项目在回答什么、凭什么可信、结论是什么、以及它有什么做不到的。

---

## 一、先讲个故事

假设你是一款出海手机游戏的**市场部负责人**。

2023 年初到 2025 年底，整整三年、156 个星期，公司花钱在五个地方给这游戏买量：

| 渠道 | 你理解的它是 |
|---|---|
| **Facebook** | 脸书上的信息流广告 |
| **Google** | 谷歌搜索、YouTube 贴片、应用商店里的广告位 |
| **TikTok** | 抖音海外版上的短视频广告 |
| **YouTube** | 油管上的视频广告 |
| **KOL** | 花钱請游戏主播、内容创作者做推广 |

三年下来，这五个渠道一共花了 **1.67 亿元**（16,698.4 万元），带来了 **4.56 亿元**（45,604.4 万元）总收入。

现在老板问你三个问题：

1. **这五个渠道，各自到底带来了多少收入？**（谁是真功臣，谁在划水）
2. **如果下个季度还是这么多钱，怎么分配能多赚点？**
3. **你这个说法，有多大把握？**

这三个问题看起来简单，实际上**非常难**。这个项目就是用来回答它们的。

---

## 二、为什么不用简单办法？（核心难点）

### 坑 1：渠道是"抱团行动"的，分不清谁的功劳

想象一下：过年促销季，市场部往往**同时在所有渠道加大投入**。那几周收入涨了——是 Facebook 的功劳？还是 TikTok 的？还是因为过年大家本来就有钱有闲？

**它们总是一起涨、一起跌**，就像一对双胞胎同时考了高分，你无法判断是哥哥聪明还是弟弟聪明，还是卷子太简单。

> 专业说法叫**共线性**（collinearity）。这个项目里，五个渠道花费的**最大相关系数达到 0.87**（关联系数从 −1 到 +1，越接近 1 表示越同步）。0.87 意味着它们几乎在同步呼吸。

### 坑 2：广告是有"余温"的，当周看不出全部效果

你今天投的广告，用户可能今天看到、明天想起来、下周才下载游戏付费。

如果只看"这周花钱、这周进账"，就会**系统性低估那些"慢热"的渠道**（比如品牌类投放），而**高估那些"立竿见影"的渠道**（比如应用商店里的下载广告）。

> 专业说法叫**广告残留**或**滞后效应**（Adstock / carryover）。数据里测得各渠道的"余温"从 0.26 到 0.42 —— 意思是本周效果的约 26%~42% 会延续到下一周，再往后再衰减。KOL 和 Google 的余温最强（0.42、0.41），说明这类内容型投放"发酵"更慢。

### 坑 3：钱投得越多，单个新用户就越贵

第一个 100 万投出去，抢的是最想玩这个游戏的人，转化率极高。到第 10 个 100 万时，剩下的都是"怎么说都不感兴趣"的人，转化率骤降。

所以**"把所有钱都给最高的那个渠道"在数学上最优，在业务上愚蠢**——那会把边际收益从"赚 3 块"拉到"赚 3 毛"，甚至亏本。

> 专业说法叫**边际递减**或**饱和效应**（Hill saturation）。数据测得最高效的 tiktok，它每多投 1 元还能赚回 **3.156 元**；而最差的 youtube 只赚回 **0.798 元** —— 已经是**投一块亏两毛**的状态了。

### 坑 4：还有一堆"不是广告但影响收入"的因素

游戏版本更新、竞品做活动、节假日、用户自然增长趋势……这些都会影响收入。

如果不把它们单独拎出来，就会**把它们的功劳算到广告头上**（或反过来，把广告的功劳算给它们）。

> 专业说法叫**遗漏变量偏误**（omitted variable bias）。这个项目把版本更新、竞品活动、节假日、长期趋势、季节性波动都单独建模了。

## 三、这个项目怎么解决？

### 3.1 核心思路：不猜一个数，而是给一个"范围"

传统做法是算出一个 ROI 数字，比如"Facebook 的 ROI = 0.68"。

问题是：**这个 0.68 有多准？** 换一批数据会不会变成 1.5？错了会不会亏钱？传统方法答不上来。

这个项目用的**贝叶斯方法**（Bayesian）换个思路：**不给一个数，给一张"可能性地图"**。

> 打个比方：老医生不会说"你血压 138.2"，而会说"你的血压大概在 130~145 之间，最可能是 138，我很确定"。后者信息量更大——它同时告诉了你**数值**和**把握程度**。

专业上这个"范围"叫**后验分布**（posterior distribution），这个范围叫**可信区间**（credible interval）。项目里所有关键结论都带区间，比如"预期提升 14.37%，94% 的可能在 638.4 万 ~ 728.3 万之间"。

### 3.2 四步走

| 步骤 | 做什么 | 用大白话说 |
|---|---|---|
| **第一步** | 造数据 | 因为真实投放数据是公司的机密，我们用程序**模拟**了一份三年的游戏出海投放数据。关键好处：**我们事先知道"标准答案"**（每个渠道真实贡献多少），可以检验模型算得准不准 |
| **第二步** | 建模 | 用贝叶斯 MMM（营销组合模型）同时处理上面四个坑：广告余温、边际递减、渠道同步、遗漏变量 |
| **第三步** | 优化 | 在"总预算不变、单个渠道调整幅度受限"的前提下，用数学规划算出**最优分配方案** |
| **第四步** | 写报告 | 把结果自动写成一份中文决策报告。**这里有个防幻觉机制**，见 5.2 节 |

## 四、结论是什么

### 4.1 五个渠道的效率排序（本项目最重要的结论）

| 渠道 | 当前周花费 | 当前周贡献 | **边际回报** | 平均 ROI | 判断 |
|---|---:|---:|---:|---:|---|
| **tiktok** | 28.4 万 | 52.0 万 | **3.156** | 1.829 | 最优，应加投 |
| **google** | 33.0 万 | 39.9 万 | **2.216** | 1.211 | 优秀，应加投 |
| **kol** | 10.1 万 | 9.3 万 | **1.632** | 0.924 | 尚可 |
| **facebook** | 20.2 万 | 13.7 万 | **1.441** | 0.679 | 偏低 |
| **youtube** | 15.3 万 | 6.3 万 | **0.798** | 0.413 | ⚠️ 亏本，应减投 |

**怎么读"边际回报"**：在当前的花钱水平上，**再多投 1 元，能多赚回多少元**。

- tiktok 的 3.156 意味着：多投 1 元 → 多赚 3.156 元。**很划算。**
- youtube 的 0.798 意味着：多投 1 元 → 只赚回 0.798 元。**投一块亏两毛。**
- **数字低于 1 的渠道就是在亏钱**，这是最直观的判断标准。

### 4.2 钱该怎么挪

在**总预算 1,391.5 万元保持不变**、**每个渠道最多只能调整 ±40%** 的前提下：

| 渠道 | 现在 | 建议 | 变化 |
|---|---:|---:|---:|
| tiktok | 369.4 万 | **517.2 万** | **+40.0%** ↑ |
| google | 428.9 万 | **518.4 万** | **+20.9%** ↑ |
| facebook | 262.6 万 | **157.6 万** | **−40.0%** ↓ |
| youtube | 199.2 万 | **119.5 万** | **−40.0%** ↓ |
| kol | 131.4 万 | **78.9 万** | **−40.0%** ↓ |

**一句话**：把钱从 youtube、facebook、kol 挪给 tiktok 和 google。

**预期效果**：同样多的钱，媒体贡献从 4,760.7 万提升到 **5,444.9 万**，**提升 +14.37%**（94% 把握落在 +638.4 万 ~ +728.3 万之间）。

### 4.3 真正的关键不在模型，在"你被允许调整多少"

这张表是本项目**最有商业洞察力**的一张表：

| 每个渠道允许调整 | 能多赚 |
|---|---:|
| ±5% | +1.36% |
| ±10% | +2.83% |
| ±20% | +6.13% |
| ±30% | +9.96% |
| **±40%** | **+14.37%** |
| ±50% | +19.40% |
| ±60% | +25.09% |
| 完全不限 | +75.73% |

**为什么不能"完全不限"？** 因为现实里有约束：渠道团队有编制和 KPI、广告账号有投放权重（突然暴涨会被平台限流）、和平台有返点商务关系、素材产能有限。**钱不是想挪就能挪的。**

**这条结论的价值**：把预算挪给高效渠道，**比纠结模型小数点后两位值钱得多**。建议先按 ±20% 执行一个季度验证，再逐步放开。

## 五、凭什么信这个结论？

这才是这个项目**最有含金量的部分**。能算出一堆数字的人很多，能说清"这些数字凭什么可信"的人很少。

### 5.1 因为我们知道标准答案

因为数据是我们**模拟**的，所以每个渠道的**真实**贡献是已知的。把模型的估计值和真值对一下：

| 检验项 | 结果 |
|---|---|
| **渠道 ROI 排序** | 模型排出来的顺序与真值顺序 **完全一致**（Spearman 相关系数 = **+1.000**，p < 0.0001）|
| **"广告余温"参数** | 5 个渠道里 **4 个命中真值**，误差小于 0.005 |
| **采样收敛** | 21 个关键参数里，**没有一个** "不收敛"（R-hat 全部 ≤ 1.01）；异常样本 **0 个 / 6000 个** |
| **参数能不能回收** | ⚠️ **部分不能** —— 见 5.3，这是诚实披露，不是掩盖 |

> **"收敛"是什么意思？** 模型内部是反复随机抽样来逼近答案的（约 6000 次）。"收敛"就是问：**它跑稳定了吗？还是还在飘？** R-hat 是衡量这件事的指标，越接近 1 越好（< 1.01 算合格）；"异常样本"（divergences）越少越好。

### 5.2 防 AI 瞎编数字的机制

项目的最后一步是用大语言模型（AI）把结果自动写成中文报告。但 **AI 会编数字**——这是它最大的风险。

所以项目做了一道**闸门**：

1. 所有数字先由程序算好，存进一张**白名单表**
2. AI 写完报告后，程序**逐个数字比对**白名单
3. 分三级判定：**完全一致**（放行）、**四舍五入能对上**（放行）、**白名单里根本没有这个数**（判定为"编造"，**整份报告作废**）

看一个**真实拦截记录**（来自 `stage4_guard.json`）：

| AI 写的 | 白名单里最接近的 | 判定 |
|---|---|---|
| "同类出海游戏的整体 ROI 约为 **88.88**" | 89.83 | ❌ **编造**（上下文里压根没有这个指标）|
| "提升 **43.7%**" | 42.9 | ❌ **编造** |
| "94%" | 94.638 | ✅ 四舍五入可接受 |
| "1.36%" | 1.3552 | ✅ 四舍五入可接受 |

104 个数字里，97 个完全一致、5 个可接受、**2 个被判定为编造 → 整份报告自动降级为模板版本**。

**这个设计的价值**：宁可出一份朴素但全对的手写模板，也不出一份华丽但混了假数字的 AI 报告。**面试时这是很好的谈资。**

### 5.3 诚实地说：有些东西算不准

一个负责任的分析必须说明**边界**。项目里明确披露了这些局限：

| 局限 | 严重程度 | 说明 |
|---|---|---|
| **基线与媒体存在结构性不可识别** | 🔴 高 | 媒体贡献里有一大块是"与广告花费波动无关的恒定分量"（报告测算约占收入的 **46.8%**）。这部分和基线常数在数学上无法分离。**后果：不要用"媒体贡献的绝对金额"，要用"渠道之间的排序"** |
| **缺少实验校准** | 🔴 高 | 这是观测数据，无法单独证明因果。业界做法是做地域实验或停投测试。**本项目没有实验数据，所以结论定位为"决策支持"而非"因果证明"** |
| **渠道共线性** | 🟡 中 | 真实投放高度同步，难以完全分离。项目通过"错峰投放"实验证明：**最大渠道相关从 0.87 降到 0.24 后，可识别性显著改善**。真实业务中建议主动安排错峰测试 |
| **参数不可识别，但 ROI 稳健** | 🟡 中 | 饱和曲线的两个参数存在"补偿关系"，单个参数不一定回到真值，但它们的**组合（即 ROI）仍能准确恢复**。结论：**参数别过度解读，ROI 和排序可以直接用** |
| **数据是模拟的** | 🟡 中 | 接入真实数据时需重新设定先验并校准 |
| **可信区间只反映参数不确定性** | 🟡 中 | 没叠加未来的市场波动和执行偏差，**实际波动会比报告区间更大** |

**三个"安全量"，对外沟通时只说这三个**：预算规模（真实货币）、提升幅度（相对值）、边际回报与 ROI（比值）。**绝对金额不要对外引用。**

### 5.4 一个漂亮的自证实验

项目专门做了一组对照实验，回答"**渠道能不能被分开，到底取决于什么？**"

| 场景 | 渠道间平均相关 | 模型恢复出的 ROI 排序准确度 |
|---|---:|---:|
| D0 纯共动（完全同步投放） | 0.52 | **−0.10**（几乎乱猜）|
| D1 中等（10 次错峰脉冲） | 0.11 | **+0.70** |
| D2 强（25 次错峰脉冲） | 0.065 | **+0.60** |
| D3 极强（50 次错峰脉冲） | 0.062 | **+1.00**（完全正确）|

**结论**：**可识别性不是算法问题，是数据设计问题。** 再好的模型也救不了一组"所有渠道一起动"的数据；而只要主动安排错峰投放，模型就能准确分离各渠道。

这条结论**直接可执行**：想让 MMM 算得准，先去安排错峰测试，而不是去换更复杂的模型。

## 六、这个东西做成了什么？

除了分析本身，项目还打包成了**三种可以亲手玩的东西**：

### 6.1 一个可交互的网页应用

用 Streamlit 做的，共 5 个页面：

| 页面 | 你能做什么 |
|---|---|
| **概览与数据** | 上传自己的投放数据（Excel/CSV 都行），或直接载入内置的模拟数据 |
| **探索性分析** | 看趋势、看渠道共线性、看广告余温、看饱和曲线。**带一张"八项支持度评分卡"**，直接告诉你"这份数据支不支持做归因" |
| **建模与诊断** | 跑模型、看收敛诊断、看各渠道 ROI 区间、看参数回收情况 |
| **预算优化** | 调约束、看最优分配、看弹性-收益曲线、看情景分析、看稳健性检验 |
| **决策报告** | 一键生成中文决策报告（可用 AI 润色，也可用模板） |

**动手提示**：进入"建模与诊断"页后，**记得点「⚡ 载入阶段 2 后验」按钮**。这样才能秒级出结果；不点的话会真的现场跑模型，要等 10~20 分钟。

### 6.2 一套可复现的分析脚本

`src/` 目录下的脚本按顺序跑一遍，就能从零复现全部结论：

```bash
python src/stage0_smoke_test.py     # 检查环境（约 1 分钟）
python src/stage1_eda.py            # 探索性分析（约 30 秒）
python src/stage2_model.py          # 建模（约 10~20 分钟）
python src/stage3_optimize.py       # 预算优化（约 3 分钟）
python src/stage4_report.py         # 生成报告
```

### 6.3 一套自动质量检查

这是**工程上最值钱的部分**——项目有 **255 条自动断言**（212 条逻辑层 + 43 条页面层），跑一遍约 40 秒：

```bash
python app/selftest_core.py   # 逻辑层 212 条
python app/uitest_views.py    # 页面层 43 条
```

**为什么这个重要？** 因为它抓到了几个**"页面看着完全正常、其实已经坏了"**的隐蔽 bug。举一个最好的例子：

> 项目里有个参数控制"每个渠道的花费缩放"。有一次这个参数没被正确挂载，导致程序**返回了"成功"**、但**提升恰好是 0**，而且五个渠道拿到了**一模一样**的预算。
>
> 页面上一切正常显示，没有任何报错。**只有对照实验才能发现它。**

这类 bug 靠"打开网页看一眼"是永远发现不了的。

## 八、还有什么可以做得更好

如果这个项目要继续推进，按优先级排：

1. **做一次地域实验或停投测试** —— 这是把"决策支持"升级为"因果证明"的唯一途径，也是 MMM 行业的标准做法
2. **主动安排渠道错峰投放** —— 实验已经证明这能把可识别性从"乱猜"提升到"完全正确"
3. **接入真实投放数据** —— 现在是模拟数据，换真实数据需要重新设定先验
4. **把优化窗口的控制变量改成预测值** —— 现在是按历史值填充的，如果未来偏离较大需要重估
