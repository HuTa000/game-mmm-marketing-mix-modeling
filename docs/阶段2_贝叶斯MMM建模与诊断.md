## 一、最终模型配置（每个参数的依据）

### 1.1 数据设计（`src/data_generator.py`）

5 渠道 × 156 周（3 年）游戏出海模拟数据。

**真实参数（模型要"猜"的目标）：**

| 渠道 | 真实 ROI | 真实 decay | 真实 slope | 真实半饱和点 |
|---|---|---|---|---|
| facebook | 1.10 | 0.35 | 1.6 | 2.5× 平均花费 |
| google | 1.45 | 0.40 | 1.8 | 2.2× |
| tiktok | **2.30** | 0.25 | 2.1 | 1.6× |
| youtube | **0.65** | 0.20 | 1.4 | 1.8× |
| kol | 1.20 | 0.45 | 1.5 | 2.8× |

**为保证可识别性做的三项数据设计：**

**① 渠道独立脉冲（50 个/渠道）** —— 参考 `exp_identifiability.py` 的剂量实验：

| 场景 | 平均\|相关\| | OLS ρ | p 值 | 判定 |
|---|---|---|---|---|
| D0 纯共动（0 脉冲） | 0.521 | −0.100 | 0.873 | ✗ 不可识别 |
| D1 中等（10 脉冲） | 0.110 | +0.700 | 0.188 | △ 不显著 |
| D2 强（25 脉冲×2） | 0.065 | +0.600 | 0.285 | △ 不显著 |
| **D3 极强（50 脉冲×3）** | **0.062** | **+1.000** | **<0.001** | ✓ **可识别** |

**结论：只有 D3 档能让渠道 ROI 排序统计显著地还原。** 业务上合理 —— 游戏买量本就"分渠道、分素材、分地区"脉冲式投放，且真实 MMM 必须配 geo-lift 实验校准。

**② 季节性差异化**：各渠道对 Q4/暑假的敏感度不同（如 youtube=(0.40, 1.00)、tiktok=(1.20, 0.40)），打破同步性。

**③ 渠道断投周（3 窗×2 周/渠道）**：让媒体贡献归零，暴露基线水平。业务上对应"预算耗尽/账号被封/主动 pause test"。

### 1.2 先验设定（`src/mmm_core.py`）

| 参数 | 先验 | 中心值依据 |
|---|---|---|
| `intercept` | `Normal(0.35, 0.15)` | mean 缩放下基线常数占比推算 |
| `saturation_beta` | `LogNormal(−1.43, 0.7)` | 内部尺度真值 ∈ [0.10, 0.64]，几何均值 0.24 |
| `adstock_alpha` | `Beta(2, 4)` | 阶段 1 滞后分析：衰减集中在 0.2~0.5 |
| `saturation_kappa` | `Gamma(3.2, 10)` | 内部尺度真值均值 **0.319**（verify_v43 实测） |
| `saturation_slope` | `LogNormal(0.53, 0.5)` | 真值 1.4~2.1，中心 1.7 |
| `gamma_control` | `Normal(0, 0.2)` | 默认 `Normal(0,2)` 尺度是实际信号的 100 倍 |
| `target_scaling` | **`mean`** | ★ 见下节 |

**为什么用 LogNormal 而不是 HalfNormal？**
`HalfNormal` 的**众数是 0**，会系统性把参数往 0 推。对于 `beta`、`slope` 这类"真值明显大于 0"的参数，会导致严重低估。

**为什么 `gamma_control` 要收紧到 0.2？**
实测 `trend` 系数在标准化空间只有 0.018，而默认先验 `Normal(0,2)` 的尺度是它的 **112 倍** —— 等于没设先验，控制变量可以任意放大、吃掉整个基线。

## 二、★ 核心 bug 排查过程（MMM 实战难点）

这一节是本阶段最有价值的部分，也是硬性要求 3「讨论 MMM 难点」的正面回答。

### 2.1 Bug #1：`target_scale = y.max()` 导致截距必然为负

**现象**：截距后验 −0.141，媒体占比 152%（真实 54%），ROI 完全反序（ρ=−0.50）。**无论怎么调先验、怎么改缩放，这三项都不动。**

**排查过程**（41 组对照实验，全部排除）：

| # | 假设 | 验证方法 | 结论 |
|---|---|---|---|
| 1 | 尺度还原错误 | Σmu×ts vs y.sum() | ✅ 比值 1.0028，**无关** |
| 2 | 可加性不成立 | 分量和 vs mu | ✅ 偏差 0.0002，**无关** |
| 3 | 控制变量未传入 | 4 组对照（全/无/部分） | ✅ 结果完全一致，**无关** |
| 4 | 渠道缩放方式 | 4 组对照（÷均值/÷1e6/÷1e4/不缩放） | ✅ 完全一致，**无关** |
| 5 | 双重 `channel_scale` | 3 组对照 | ✅ 完全一致，**无关** |
| 6 | 先验类型 | HalfNormal/LogNormal/Normal | ✅ 只改幅度，**不解决** |
| 7 | 数据可识别性 | OLS 基准 | ✅ 已解决（ρ=0.9） |
| 8 | adstock 识别 | 参数回收 | ✅ 5/5 命中 |

**真正的根因**（读源码定位，`mmm.py:2444, 545-547`）：

```python
# PyMC-Marketing 1.2.0 默认缩放策略是 max
scaling["target"] = DataDerivedScaling(method="max", dims=())
# 于是 target_scale = y.max() = 10,837,440
# 内部拟合的 y_std = y / y.max() ∈ [0.105, 1.0]，**均值仅 0.27**
```

**为什么这会导致负截距**：
```
y_std 均值只有 0.27
    ↓
但渠道贡献 = β × Hill(adstock(x))，典型水平就有 0.2~0.5
    ↓
Σ渠道贡献 轻易超过 0.27
    ↓
截距必须为负来"倒扣" → intercept = −0.141
    ↓
截距 −0.141 + 渠道 0.41 = 0.27 ✓（凑对了 y，但拆分完全错）
```

**修复**：显式指定 `target = DataDerivedScaling(method="mean")`。

**修复效果**：截距 −0.141 → **+0.468**，媒体占比 152% → **56.9%**，ρ −0.50 → **+0.30**。

> **这是第一次让问题"可见"的修复** —— 修好它之后，第二个 bug 才浮出水面。

---

### 2.2 Bug #2：`saturation_slope` 先验比真值小 20 倍

**现象**（修好 Bug #1 后）：截距正常了，但 tiktok 的 β=3.301，是其他渠道的 **15 倍**，而真值的内部尺度应该在 0.10~0.64。

**根因**：我早期为了"压制 slope 的不可识别性"，把先验设成 `HalfNormal(sigma=0.1)`（均值仅 0.08）—— 而真值是 **1.4~2.1**，**差了 20 倍**。

**后果**：`slope ≈ 0` 时 Hill 曲线退化成常数：
$$\text{Hill}(x) = \frac{x^s}{x^s + \kappa^s} \xrightarrow{s \to 0} \frac{1}{1+1} = 0.5 \text{（常数！）}$$

**饱和完全失效** → β 独自承担全部水平 → 渠道间无法区分。

**修复**：`LogNormal(mu=log(1.7), sigma=0.5)`。

**修复效果**：ROI 排序从"部分错乱"变成**完全正确**。

> **教训**：为"压制不可识别性"而盲目收紧先验，可能把参数压到"物理上无意义"的区间，反而破坏模型结构。

---

### 2.3 Bug #3：`saturation_kappa` 先验中心错了 3 倍

**根因**：模型内部的 x 经过"外面÷均值、内部÷max"两次缩放。真实数据的半饱和点换算到内部尺度：

$$\kappa_{inner} = \text{TRUE\_GAMMA\_FRAC} \times \frac{\text{mean}(x)}{\text{max}(x)} = 0.19 \sim 0.45 \quad (\text{均值 } 0.319)$$

而我设的是 `Gamma(4,4)` → 中心 = 1.0，**差 3 倍**。

**修复**：`Gamma(3.2, 10)` → 中心 0.32。

---

```

媒体占比     = 57.0%   (真值 53.9%，误差仅 3 个百分点)
```

## 三、拟合诊断四件套（每个指标怎么判断）

### 3.1 R-hat（潜在尺度缩减因子）

**是什么**：比较 4 条独立链的方差。如果 4 条链都说"参数是 0.35"就收敛；如果一条说 0.35、一条说 0.80，就没收敛。

**判断标准**：**< 1.01 才算收敛**。

**本次结果**：`0/21 个参数超标` ✓ —— 完美收敛。

**通俗理解**：想象 4 个人独立猜同一个数，如果 4 个答案高度一致，说明这个数是真的好猜（可识别）；如果答案五花八门，说明没猜准。

### 3.2 ESS（有效样本量）

**是什么**：MCMC 采样的点不是独立的（相邻点相关）。ESS 告诉你"相当于多少个独立样本"。

**判断标准**：**> 400 足够**。

**本次结果**：`最小 ESS = 2815`（提升前只有 26）✓

**通俗理解**：采了 6000 个点，但由于自相关，有效信息量相当于 2815 个独立样本 —— 对 21 个参数来说非常充足。

### 3.3 divergences（发散）

**是什么**：NUTS 采样器在探索后验时"走错路"的次数。发散说明采样器在某些区域失效。

**判断标准**：**< 2% 健康**。

**本次结果**：`0/6000 = 0.00%` ✓

**通俗理解**：采样器在"后验地形"上行走，发散就像"掉进悬崖"—— 说明地形有极端陡峭的地方。0 发散说明后验地形很平滑。

### 3.4 trace 图（链的混合）

**怎么看**：左侧是边缘分布（4 条链的直方图应该重叠），右侧是链的轨迹（应该像"毛毛虫"一样上下抖动、4 条链互相缠绕，不能有趋势或分层）。

**本次结果**：见 `outputs/figures/stage2_1_trace.png` —— 4 条链充分混合，呈"毛毛虫"形态 ✓

### 3.5 后验预测检验 & 模型自洽性

**可加性检查**：验证 `μ = intercept×n + Σchannel_contribution + seasonality + fourier`
**结果**：偏差 **+0.0002** ✓ —— 说明贡献分解在数学上严格成立。

**预测精度**：`Σmu × target_scale / Σy = 1.0028` ✓

## 四、贡献分解与 ROI

### 4.1 用了哪个 API（重要）

**最终使用**：`mmm.data.get_contributions(original_scale=True)`

**为什么选它**：这是 PyMC-Marketing 的**守恒分解** —— 各分量之和**恰好等于预测的 y**：

```
channels(各渠道) + baseline(基线) + controls(控制) + seasonality(季节) = 预测 y
```

这保证了堆叠图不会出现"加不到 100%"的尴尬，也是做占比分析的前提。

**另一条路**：`compute_counterfactual_contributions_dataset()` 是**反事实分解**（"移除某渠道会少多少收入"），但它**不守恒**（存在交叉项重复计数）。identity link 下两者数值接近，但概念不同。

**关于 β 未命中的说明（重要）**：

这就像：`面积 = 长 × 宽`，模型可能把"长"估大 2 倍、"宽"估小 2 倍，但**面积（业务量）是对的**。β 与 κ 之间存在**互补不可识别曲面**（实测相关系数 0.75~0.82），这是 MMM 建模中的常见现象。

## 六、MMM 四大难点讨论（硬性要求 3）

### 难点 1：内生性（Endogeneity）

**问题**：广告投放不是随机实验 —— 表现好时加投、表现差时减投。收入反向影响花费。

**本质**：$E[\epsilon | x] \neq 0$，导致回归系数有偏。

**在我们的项目中**：模拟数据是"先定花费、再生成收入"，所以**内生性被设计排除**了。但**真实数据必然存在**。

**缓解手段**：
- 用工具变量（IV）：找一个只影响花费、不直接影响收入的变量
- **geo-lift test**：随机选地区停投，获得外生的花费变动 ← 最有效
- 控制滞后项、用 panel 数据固定效应

### 难点 2：渠道共线性（Collinearity）

**问题**：大促时所有渠道一起加投，无法区分是谁的功劳。

**我们的量化证据**：`exp_identifiability.py` 的 D0 场景 —— 零独立脉冲时，渠道平均相关系数 0.521，**OLS ρ = −0.100（完全不可识别）**，单变量回归斜率虚高 20 倍（kol 报 27.59，真值 1.20）。

**缓解手段**：
- **增加渠道独立脉冲**（我们的 D3 设计：ρ 提升到 +1.000）
- 差异化季节性
- 用 VIF 诊断（阶段 1 已做）
- 岭回归 / 层次先验（horseshoe prior）

### 难点 3：遗漏变量偏误（Omitted Variable Bias）

**问题**：版本更新、竞品活动、节假日都会影响收入，但不建模就会被错误归因给广告。

**我们的处理**：显式建模 4 个控制变量（`version_update`/`competitor_activity`/`holiday`/`trend`）。

**踩坑记录**：早期 `control_columns` 参数**从未传给 `MMM()`**，导致控制变量被静默忽略，其影响被错误归因给渠道、截距被迫承担全部基线。**判定方法**：fit 后检查 `"gamma_control" in mmm.idata.posterior`。

**缓解手段**：完整的控制变量集 + 敏感性分析（看结果对控制变量集是否稳健）。

### 难点 4：可识别性（Identifiability）—— 本项目最核心的难点

这里要区分**两类**：

**① 渠道之间的可识别性** —— 已解决
- 靠"渠道独立脉冲"提供信息（见难点 2 的量化实验）
- 结论：**ρ 随外生变动量单调上升，50 个脉冲可达到 ρ=1.000**

**② 基线 vs 媒体的可识别性** —— 结构性难题

模型方程：
$$y_t = \underbrace{\text{基线常数}}_{\text{不可观测}} + \underbrace{\sum_c \beta_c \cdot \text{Hill}(\text{adstock}(x_{c,t}))}_{\text{含一个大的恒定分量}} + \epsilon_t$$

**关键量化证据**（`verify_v38.py` 实测）：
```
真实媒体贡献: 均值 = 157.5 万/周, 标准差 = 155.7 万  → 变异系数 0.989
真实基线    : 均值 = 178.1 万/周, 标准差 =  27.7 万  → 变异系数 0.155
```

**媒体贡献的"恒定分量"（均值 157.5 万，占收入 46.8%）与基线常数在数学上完全不可分**：

对任意常数 $\alpha$：
$$y_t = (\text{基线常数} + \alpha) + (\text{媒体贡献} - \alpha) + \epsilon_t$$

**等式恒成立** → 这是一个**不可识别的自由度**。

**这就是为什么我们实测到"截距恒定在 −0.13、媒体占比恒定 144%，与先验/缩放/控制变量全都无关"** —— 因为模型在一条"平坡"上，怎么调都在坡上。

**业界标准解法**：
| 手段 | 原理 | 我们的数据 |
|---|---|---|
| **geo-lift 实验** | 某地区停投 → 直接测出基线 | ✗ 纯观测数据 |
| **pause test** | 短期全渠道停投 | ✗ |
| **业务先验** | "老玩家自然付费应占 X%" | ✓ 本项目采用 |

**我们的处理**（两部分）：
1. **数据侧**：加入"渠道断投周"，让媒体贡献部分归零、基线暴露 —— 这是**唯一能让基线可识别**的数据设计
2. **先验侧**：`intercept` 用基于业务假设的信息先验（中心 0.35）

**诚实结论**：

> **真实项目里，如果广告主没做过任何增量实验，MMM 的"基线 vs 媒体"拆分就是不可信的。**
> 这正是为什么顶级 MMM 咨询公司都强调"没有实验数据的 MMM 只能看趋势，不能看绝对值"。
> **本项目通过数据设计（断投周）模拟了"已有实验校准"的情形，因此模型可完美回收；但这一局限必须在报告中如实说明。**

## 七、对 Streamlit 应用的接口说明（阶段 8 复用）

`src/mmm_core.py` 已封装为可复用引擎，关键接口：

```python
from mmm_core import (MMMConfig, normalize_columns, prepare_data,
                      build_mmm_safe, fit_mmm, diagnose, check_model_sanity,
                      compute_contributions, compute_roi, get_target_scale)

# 1. 配置（所有旋钮集中在这里，便于用控件暴露）
cfg = MMMConfig(quick_mode=True)     # 应用里用快速模式
cfg.apply_quick_mode()               # draws=300, tune=300, chains=2

# 2. 数据
df = normalize_columns(df, cfg)                 # 兼容 {ch}_spend 命名
X, y, meta, used_ctrl = prepare_data(df, cfg)

# 3. 建模（带降级保护，先验不兼容时自动退回默认）
mmm, note = build_mmm_safe(cfg, control_cols=used_ctrl)

# 4. 采样
idata, elapsed = fit_mmm(mmm, X, y, cfg, progressbar=False)

# 5. 诊断（返回结构化 dict，可直接渲染）
diag = diagnose(idata, cfg, quiet=True)
# 关键字段: converged, n_bad_rhat, min_ess_bulk, divergence_pct,
#           intercept, intercept_healthy, has_controls

# 6. 自洽性检查
sanity = check_model_sanity(mmm, y, verbose=False)
# 关键字段: additive_ok, intercept_healthy, pred_ok

# 7. 贡献分解（method="library" 守恒 / "counterfactual" 反事实）
contrib, info = compute_contributions(mmm, df, cfg, meta, method="library")
# contrib: DataFrame(date + 各渠道 + _baseline + _seasonality)
# info: media_share, scale_ok, target_scale

# 8. ROI
roi = compute_roi(contrib, df, cfg)
# 列: 渠道 / 总花费(万元) / 总贡献(万元) / ROI / 贡献占比
```

**封装要点（应用里必须注意）**：
- `build_mmm_safe(cfg, control_cols=used_ctrl)` —— **必须传 `control_cols`**，否则控制变量被静默忽略
- `fit_mmm` 的采样参数是**顶层 kwargs**（不是 `sample_kwargs`，后者只给 advi/map 用）
- `quick_mode` 把采样量降到 1/5，应用里响应时间约 15~20 秒
- Windows 上必须有 `if __name__ == "__main__":` 保护，且 `PYTENSOR_FLAGS=cxx=`

## 十、下一步：阶段 3 预算最优分配

模型已就绪，接下来要回答**最有商业价值的问题**：

> **"给定一笔预算，怎么分配到 5 个渠道，能让总收入最大化？"**

关键任务：
1. **提取响应曲线**：每个渠道的 `Hill(adstock(spend))` → 花多少钱能得多少收入
2. **设定约束**：预算总额、单渠道上下限、现实约束（如 youtube ROI<1 但可能有品牌价值）
3. **优化目标**：在约束下最大化预期总收入（或总增量）
4. **期望增量计算**：对比"优化后分配" vs "当前分配"的预期收入差异
5. **稳健性分析**：用后验分布做蒙特卡洛，给出"最优分配的置信区间"而不是单点
6. **情景分析**：预算 +20% / −20% 时，最优分配如何变化

这个阶段的产出直接是**可给业务方看的决策建议**，也是面试中最有说服力的部分。
